# Ревью-канал: как ревьюер и кодер общаются через репозиторий

Здесь лежат разборы работы кодер-моделей. Один файл — одно ревью.

## Зачем это нужно

Кодер-модель пишет код в отдельной ветке и не видит ни истории обсуждений, ни
причин, по которым план устроен именно так. Ревью в чате исчезает вместе с
сессией. Ревью в репозитории — остаётся: его читает следующая модель, к нему
можно вернуться через месяц, и по нему потом пишется методическая часть диплома
(«как выявлялись и устранялись дефекты»).

## Именование

```
docs/reviews/<ГГГГ-ММ-ДД>-<что-ревьюилось>.md
```

Например `2026-08-24-steps-2.2-3.3.md`. Дата — когда ревью проведено, не когда
писался код.

## Структура файла ревью

1. **Сводка** — что проверялось, чем проверялось, каков статус проверки.
2. **Находки** — по убыванию тяжести, каждая с `файл:строка`.
3. **Что сделано хорошо** — не вежливость: это фиксирует удачные решения,
   чтобы следующая модель их не сломала при рефакторинге.
4. **План работ** — упорядоченный список задач с критериями приёмки.
5. **Открытые вопросы** — то, что решает человек, а не модель.

## Обязательная разметка каждой находки

**Тяжесть:**

| Метка | Значение |
|---|---|
| 🔴 блокер | До исправления не запускать платную GPU-сессию |
| 🟠 серьёзно | Жжёт время сессии или ведёт к неверным выводам |
| 🟡 средне | Латентный дефект: сегодня не стреляет, завтра выстрелит молча |
| ⚪ мелко | Опечатки, комментарии, расходящиеся с кодом |

**Статус проверки** — обязателен, потому что часть кода физически не запускается
на маке (нужен `mani_skill`, то есть Linux + CUDA):

| Метка | Значение |
|---|---|
| ✅ выполнением | Прогнано локально (`pytest`, `ruff`, скрипт) |
| 📖 чтением | Проверено по исходникам, но не запущено |
| ❓ не проверено | Требует сервера; принимать как гипотезу, не как факт |

## Как кодеру отвечать

Не переписывать файл ревью. Под каждым пунктом, который взят в работу,
добавлять строку:

```
**Статус:** исправлено в <коммит/ветка> — <что именно сделано>
```

Если пункт отклоняется — писать почему. Несогласие с ревью нормально; молчаливое
игнорирование — нет.

## Правила, унаследованные из плана

Действуют и здесь (см. [../implementation-plan.md](../implementation-plan.md) §0):

- Язык кода, комментариев и докстрингов — английский. Язык планов и ревью —
  русский.
- Сомнительные места помечаются `# TODO(review)`. Другие конвенции пометок не
  заводить: таблица открытых вопросов в
  [../server-runbook.md](../server-runbook.md) ищет именно эту строку.
- API ManiSkill сверяется с реальным исходником на теге `v3.0.1`, а не по
  памяти.
