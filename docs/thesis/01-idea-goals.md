# 01 – Идея, цель, задачи

## Идея

Две руки-манипулятора типа **SO-100** (Standard Open Arm 100; открытое железо LeRobot / TheRobotStudio, 5 DOF + захват), каждая – самостоятельный **агент**, совместно собирают кубик Рубика. Координация **децентрализованная**:

- на исполнении агент видит только **своё** наблюдение (проприоцепция + своя камера);
- **нет центрального контроллера** и **нет явного обмена сообщениями**;
- согласование («кто держит, кто крутит», синхронизация перехватов) возникает за счёт того, что каждый агент **предсказывает латентное состояние партнёра** – механизм **Bi-JEPA**.

### Декомпозиция задачи

Физическая сборка кубика двумя руками – длинногоризонтная контактная задача, плоский RL на весь солв нереален. Иерархия:

1. **Высокий уровень (готовый солвер):** Kociemba / God's algorithm выдаёт последовательность поворотов граней (~20 ходов). Это классический алгоритм, **не** обучается.
2. **Атомарный примитив (обучается RL + Bi-JEPA):** «повернуть грань на 90°» – удержание корпуса одной рукой + твист грани другой, при необходимости переориентация кубика и **смена ролей** между руками.
3. **Полная сборка = цепочка примитивов** по списку солвера.

Именно на уровне атомарного бимануального примитива живёт научная часть: децентрализованная координация ролей «холдер ↔ ротатор» без центрального арбитра – естественная площадка для Bi-JEPA.

### Что обучается, а что берётся готовым

| Компонент                                          | Кто решает                  |
| -------------------------------------------------- | --------------------------- |
| Последовательность поворотов (какие грани крутить) | классический солвер         |
| Низкоуровневое управление руками                   | RL (обучается)              |
| Координация рук (роли, синхронизация)              | RL + Bi-JEPA (обучается)    |
| Восприятие состояния кубика (зрение)               | обучается (фаза со зрением) |

## Цель

Разработать и экспериментально проверить **JEPA-подход к децентрализованной координации двух манипуляторов** – не-реконструктивное латентное предсказание состояния партнёра – на задаче бимануальной манипуляции, с переносом **sim2real** на реальные SO-100, и продемонстрировать его преимущество над реконструктивными / дистилляционными подходами к моделированию партнёра.

> Формулировка заострена **после** обзора литературы: базовая идея «латентная децентрализованная координация» уже застолблена (2025–26), поэтому вклад смещён в сторону *JEPA-формулировки* + *sim2real на реальном дешёвом железе* + *систематического сравнения*. См. [02](02-related-work.md).

## Задачи

1. Собрать GPU-симуляцию двух SO-100 в ManiSkill; смоделировать кубик (turntable-абстракция → гибридная артикуляция для цепочки ходов).
2. Поднять децентрализованный MARL-бейзлайн (IPPO / MAPPO) на бимануальной задаче.
3. Спроектировать и реализовать Bi-JEPA: энкодер наблюдений + предсказатель латента партнёра; интегрировать предсказание в политику.
4. Провести ablation *oracle / predicted / no-partner* и сравнение с teammate-бейзлайнами (реконструктивный à la Dreamer, дистилляционный à la CLS-DP).
5. Ввести зрение (V-JEPA) и выполнить перенос sim2real на реальные SO-100.
6. Свести результаты, сформулировать выводы.

## Ключевые проектные решения (сводка)

| Параметр  | Решение                                                               |
| --------- | --------------------------------------------------------------------- |
| Платформа | Sim2Real (учим в симуляции → переносим на железо)                     |
| Парадигма | Децентрализованный Multi-Agent RL + Bi-JEPA поверх                    |
| JEPA      | Адаптация существующих (V-JEPA / world-model JEPA от Meta), не с нуля |
| Железо    | 1× A100 80GB (сервер лаборатории)                                     |
| Стратегия | Сначала быстрый бейзлайн, потом полный Bi-JEPA; state-space → vision  |
