# 03 – Метод: Bi-JEPA + MARL

## Напоминание: что такое JEPA

Joint-Embedding Predictive Architecture (LeCun, 2022) – предсказывать **представление** (эмбеддинг) целевого сигнала из представления контекста, **в латентном пространстве** (не реконструкция пикселей). Против коллапса представлений – асимметрия: **target-энкодер** (часто EMA онлайн-энкодера, stop-gradient на цели) + предиктор. Семейство: I-JEPA (изображения), V-JEPA / **V-JEPA 2** (видео; 2-AC – action-conditioned world-model с планированием).

## Формулировка Bi-JEPA

Для каждого агента $i \in \{1,2\}$:

- **энкодер** $E:\; o_i \rightarrow z_i$ – своё наблюдение в латент;
- **предсказатель партнёра** $P$: из истории своих латентов $z_i^{\le t}$ (и, опционально, своего плана действий) предсказывает **будущий латент партнёра** $\hat z_j^{t+k} \approx z_j^{t+k}$, где цель $z_j = E(o_j)$;
  - лосс – **в латентном пространстве**, `stop-grad` на цели, target-энкодер по EMA (или заморожен, если энкодер предобучен);
  - горизонт $k>1$ – предсказание *будущего* для антиципации манёвра партнёра;
- **политика** $\pi_i$: действие на основе $o_i$ и предсказанного $\hat z_j$ → **координация без обмена сообщениями** на исполнении.

«**Bi**» – оба агента симметрично моделируют друг друга. По сути это **JEPA-версия agent-modeling в парадигме CTDE-MARL** (см. позиционирование новизны – [02](02-related-work.md)).

## MARL-постановка

- **Алгоритмы:** IPPO (независимый PPO на каждую руку, чистая децентрализация) + MAPPO (централизованный критик, CTDE) – как decentralized-vs-CTDE компараторы. Библиотека – **BenchMARL** (поверх TorchRL).
- **CTDE (решение D):**
  - *исполнение:* политика $\pi_i$ видит только $o_i$ + предсказанный $\hat z_j$ (децентрализовано);
  - *обучение:* критик MAPPO видит **глобальное состояние** (обе руки + кубик); цель предсказателя (истинный $z_j$) доступна из наблюдения партнёра по CTDE.
- **Параметры политики:** общие веса + agent-id (в симметричной фазе). Для асимметричных ролей (холдер/ротатор) – либо role-conditioning, либо раздельные головы.

## Решения по архитектуре (A–E)

| #     | Вопрос                       | Решение                                                                                                                         | Альтернатива                                                           |
| ----- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| **A** | Что кодирует V-JEPA (фаза 2) | Замороженный предобученный **V-JEPA 2** на **wrist-камере** каждого агента (эго-вид уважает децентрализацию, лучше переносится) | внешняя камера; finetune энкодера                                      |
| **B** | Механизм «Bi»                | Предсказание **латента партнёра без связи** (core); learned-comms – опц. условие сравнения; цель – будущий латент, $k>1$        | общий joint world-model                                                |
| **C** | Обучение предсказателя       | **Aux JEPA-лосс совместно с RL**, EMA/stop-grad target; ablation-тройка = тумблер входа политики                                | претрен предсказателя на роллаутах (стабильнее, но distribution shift) |
| **D** | Инфо-асимметрия              | **CTDE** (см. выше) – предопределено                                                                                            | –                                                                      |
| **E** | Model-free vs планирование   | **Model-free ядро** (Bi-JEPA = представление + предсказание под PPO)                                                            | латентное планирование (V-JEPA 2-AC) – опц. расширение фазы 3          |

**Связка A↔C:** замороженный энкодер даёт *фиксированную* цель-латент → нет риска коллапса, лосс предсказателя = чистая регрессия к фиксированным латентам партнёра (упрощает C). Обучаемый энкодер требует полной анти-коллапс машинерии JEPA (EMA, stop-grad).

**Тонкость A (sim2real):** предобученный на реальном видео V-JEPA на рендерах ManiSkill даёт **domain gap** → решать domain randomization рендера или лёгким адаптером/LoRA.

## Стадийность (ключевая развилка)

Новый вклад (механизм координации B/C/D) валидируется **сначала в пространстве состояний**, до тяжёлого зрения:

- **Фаза 1 – state-space Bi-JEPA:** энкодер = MLP по проприоцепции + состоянию кубика → латент; предсказатель партнёра = MLP; в PPO. Дёшево, гоняется на текущем стеке. Даёт первый сигнал по ablation-тройке. *Если oracle ≈ no-partner даже здесь – важный ранний негативный результат.*
- **Фаза 2 – vision Bi-JEPA:** свап state-энкодера на замороженный V-JEPA на wrist-камере; та же машинерия предсказателя+политики. Релевантно sim2real.
- **Фаза 3 (опц.) – латентное планирование** (à la V-JEPA 2-AC).

Стадийность развязывает A от B/C/D и де-рискует диплом.

## Открытые вопросы метода

- Точная цель предсказания: латент партнёра из *его* наблюдения vs привилегированного состояния партнёра (по умолчанию – из его наблюдения, консистентнее).
- Горизонт $k$ и как кондиционировать предсказатель на собственный план агента.
- Domain randomization и адаптация энкодера для sim2real (фаза 2).
- Нужен ли warmstart (скриптовый эксперт: подвод→захват→твист) при тяжёлой сходимости.

## Реализация (3.1)

Код: `callosum/agents/bijepa.py` (чистый PyTorch), гиперпараметры – `callosum/configs/bijepa.py`, тесты – `tests/test_bijepa.py`.

- **Энкодер** – MLP `o_i → z_i` (по умолчанию 2×256, tanh, LayerNorm, латент 32, линейный выход без нормировки). Агенты индексируются 0 (холдер) и 1 (ротатор). По умолчанию у каждого агента **свой энкодер** (`shared_encoder=False`), так как наблюдения различаются по составу/размеру; общий энкодер возможен при равных размерах.
- **Предсказатель** – свой у каждого агента. Вход – окно собственных латентов `(B, K, d)`; по умолчанию `K=1` (окно из одного текущего латента, буфер истории в тренере не нужен), агрегация `flatten` (`(B, K·d)` → MLP) или `gru`. Горизонт $k>1$ задаёт вызывающий код: в последний слот `obs_hist_partner` кладётся наблюдение партнёра в момент $t+k$.
- **Цель** $z_j$ считается из наблюдения партнёра **target-энкодером партнёра** («собственный латент партнёра») под stop-grad. По умолчанию – **EMA-копия** (`ema_momentum=0.99`, `update_target()` после каждого шага оптимизатора, параметры с `requires_grad=False`); без EMA – онлайн-энкодер партнёра под `no_grad`.
- **Лосс** – MSE в латентном пространстве; `forward_both` усредняет оба направления (a→b и b→a).
- **Анти-коллапс.** Обучаемый энкодер + одна лишь stop-grad цель допускает тривиальное решение $z=\mathrm{const}$: на архивной ветке SO-100 разброс латентов сжался в 4.4 раза за 156 обновлений при «красиво» убывающем лоссе. Поэтому по умолчанию сразу три защиты: (а) EMA-цель; (б) VICReg-подобный регуляризатор на онлайн-латентах (вариационный hinge `relu(1 − std)` с весом 1.0 и ковариационный штраф с весом 0.04, соотношение 25:1 из VICReg, пересчитанное на единичную дисперсию) – hinge обращается в ноль при std ≥ 1, т.е. это «пол», а не сила, раздувающая латент; отключается нулевыми весами; (в) диагностика `latent_stats(z)`: среднее/минимум std по измерениям и эффективный ранг (RankMe) – её нужно логировать в 3.2 (ранг масштабно-инвариантен, поэтому смотреть вместе со std).
