# server-storage Specification

## Purpose

Хранение и обновление на вычислительном сервере: персистентный layout в `$HOME`, скрипты `setup_server.sh` / `update_server.sh`, обработка причуд SAPIEN/Vulkan. Существующее поведение «как есть» (в `main`); серверная верификация скриптов отложена до первого cloud-прогона.

## Requirements

### Requirement: Персистентный layout в $HOME

Всё тяжёлое SHALL жить в персистентном `$HOME` (100 ГБ, переживает рестарт контейнера): checkout `~/callosum`, venv и кэши (uv, Hugging Face, ManiSkill/SAPIEN, Vulkan-loader) под `~/.callosum`, результаты — `~/callosum-runs`, достигаемые через symlink `runs/` в checkout; архивы завершённых прогонов — `~/callosum-archive`. Оверлей `/tmp` стирается при рестарте — только временные файлы. Переменные окружения для новых терминалов — `~/.callosum-env.sh` (переписывается каждым запуском setup, подключается через `~/.bashrc`).

#### Scenario: Рестарт контейнера ничего не стоит

- **WHEN** контейнер сервера перезапускается
- **THEN** checkout, venv, кэши и `runs/` на месте; продолжение прогона — `--resume` из последнего чекпоинта; повторной загрузки torch/PhysX нет

#### Scenario: Старый /tmp-layout распознаётся

- **WHEN** setup встречает унаследованный env-файл со ссылками на `/tmp` и висячий `~/.sapien`
- **THEN** мёртвые экспорты игнорируются с предупреждением, висячая ссылка заменяется реальным каталогом (с копированием содержимого, без удаления), `runs/` и архивы не трогаются

### Requirement: update_server.sh — жёсткая синхронизация

`bash scripts/update_server.sh` SHALL обновлять checkout до последнего запушенного кода и перезапускать `setup_server.sh` (идемпотентно, быстро без изменений). Это жёсткая синхронизация, не `git pull`: `git fetch --prune origin` (с тайм-аутом), затем `git checkout -B <branch> origin/<branch>` — переписанная (force-pushed) история не проблема. Опции: `--branch <name>` (переключить ветку), `--force` (отбросить локальные правки отслеживаемых файлов), `--no-setup` (только код), `-- ...` (аргументы в setup). Незакоммиченные правки отслеживаемых файлов отклоняются (печатаются) без `--force`; неотслеживаемые и игнорируемые файлы (symlink `runs`, логи) сохраняются — `git clean` нет. Если сам скрипт изменился в обновлении, новая версия перезапускается автоматически. Код на сервере не правится.

#### Scenario: Обновление безопасно после force-push

- **WHEN** удалённая история ветки переписана и `update_server.sh` запущен
- **THEN** checkout приводится к `origin/<branch>` (печатается старый → новый коммит и `git diff --stat`), setup доустанавливает окружение

#### Scenario: Правки на сервере отклоняются

- **WHEN** в checkout есть незакоммиченные правки отслеживаемых файлов и нет `--force`
- **THEN** скрипт печатает их и останавливается, не затирая

### Requirement: setup_server.sh — идемпотентная установка и проверки

`bash scripts/setup_server.sh` SHALL выполнять идемпотентную установку и проверки: проверяет Linux + `nvidia-smi`; выбирает layout (home по умолчанию; scratch только по запросу или при < 30 ГБ свободного места); ставит uv в `~/.local/bin`, Python 3.12, синкает `sim` + `train` + `dev` из `uv.lock` (`--frozen`, без ресолва — рассинхрон lock/pyproject отклоняется); устраняет причуды SAPIEN (неверсионированный `libcuda.so`, Vulkan-устройство — пробирует кандидатов в свежих процессах, берёт первый, который строит `RenderMaterial()` и `RenderSystem("cuda:0")`; lavapipe — только fallback), предзагружает PhysX GPU-библиотеку в `~/.sapien`; верифицирует: torch CUDA build, реальный CUDA matmul, compute capability против версии CUDA, импорт `mani_skill`, агент `so101_pg`, регистрация `TwoSO101-v0` / `FaceTurn-v0`; с `--smoke` гоняет GPU-проверки (`smoke_env.py`, `smoke_face_turn.py`).

#### Scenario: Повторный запуск быстрый

- **WHEN** setup вызывается повторно без изменений зависимостей
- **THEN** кэши и venv переиспользуются (секунды), проверки повторяются, env-файл переписывается

### Requirement: Верификация отложена до первого прогона на Nebius

Скрипты storage-слоя написаны вслепую под лабораторный сервер (JupyterHub, A100, доступ только через веб-терминал) и на нём больше не проверяются: лабораторный сервер недоступен, compute переведён на Nebius (Preemptible L40S, eu-north1; ранбук `docs/cloud-gpu.md`). Первый прогон на VM (`bash scripts/setup_server.sh --smoke`) MUST верифицировать `scripts/update_server.sh` и персистентный layout; `main` заморожен до этой верификации.

#### Scenario: Первый cloud-прогон валидирует скрипты

- **WHEN** VM Nebius создана и на ней запущена первая установка по ранбуку
- **THEN** работа `update_server.sh` / `setup_server.sh` и персистентность layout проверяются и фиксируются в отчёте до влива в `main`
